# VEILWARDS v4.2.1 — ONLINE FRIENDS PLAYTEST

This folder is already prepared to host Veilwards and its multiplayer room server together on **one HTTPS address**. Do not upload only the solo HTML to itch.io: the room server must run too.

## Publish once (Render + GitHub)

1. Extract the downloaded ZIP. You should see `index.html`, `game3d.mjs`, `server.js`, `package.json`, and `render.yaml` **directly inside the folder**.
2. On GitHub, create a new repository, e.g. `veilwards-playtest`.
3. In the repository, choose **Add file > Upload files**. Upload the **contents of this folder into the root of the repository**, not the ZIP itself and not an enclosing subfolder. Commit the files.
4. On Render, choose **New > Web Service**, connect your GitHub repository, and choose the free instance (if available). Set runtime **Node**, build command **`npm install`** and start command **`npm start`**. Render chooses a `PORT` for the app automatically. For lower latency you can choose a region near your players (e.g. Singapore if offered).
   - Alternatively, choose **New > Blueprint** and connect the same repository to use the provided `render.yaml`.
5. When deployment succeeds, Render shows a public address similar to `https://your-service.onrender.com`. Visit it to play.
6. Tap **Multiplayer > Create**. In the room lobby, tap **Share invite link**. Your friends on Android or PC can open that link, enter a name, and tap **Join**. The room code will already be filled in. When everyone arrives, the **host** taps **Start opening draft**.

The game and multiplayer relay share the same origin, avoiding separate server addresses or CORS configuration.

## Things to know

- This is a FRIENDS-ONLY PROTOTYPE, not a hardened public live service. Choose a hard-to-guess room code automatically generated by the game; don't share your room link publicly if you want it private.
- The **host's browser still runs the simulation**, with guests receiving snapshots. The host must keep their tab open during a match. If the host closes/reloads the tab, the session will be interrupted.
- **Rooms and progress exist in the server's memory**, so a server restart/redeploy loses active sessions.
- Render's free services may spin down after 15 minutes of inactivity and take roughly a minute to wake up. The first visitor may see a startup delay.
- The Three.js renderer currently loads its pinned module from jsDelivr; players need Internet access.
- No third-party sign-in is required for players; up to four total players per room.
- Android and PC share the same multiplayer web link. The usual device/browser graphics limitations still apply.
- To test locally, run `Start_Windows.bat` (Windows) or `npm start` with Node.js 20+.

## Files

- `index.html` / `game3d.mjs` — game interface and renderer/gameplay code
- `server.js` — Node.js HTTP + SSE room relay (also serves the game)
- `package.json` — start command for Render
- `render.yaml` — optional Render Blueprint
- `Start_Windows.bat` — local testing launcher
